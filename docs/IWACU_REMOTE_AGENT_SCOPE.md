# Iwacu Agent (voice remote) — Scope and Integration Notes

**Branch:** feat/iwacu-remote-agent-20261121  
**Base:** existing main  
**Status:** isolated feature work; not merged and not deployed.

## Product boundary

Iwacu Agent is a voice remote control for the existing IWACU RWANDA site, like a TV remote operated by speaking. It is not a new site, a replacement assistant or a redesign.

- One audio icon in AppHeader. One tap switches the agent on: it greets by voice ("Muraho. Ndakumva neza. Twifuza ko tugufasha gute?") and listens. Nothing opens on screen; the site stays as it is and is operated by voice (location, emergency numbers, reading a page, opening existing sections, asking questions, calling a verified number after a spoken "yego").
- The icon shows it is on (yellow ring and a soft pulse). Tapping it again, or saying "funga", switches it off.
- The written conversation is optional: a long press on the icon, or saying "erekana ibyo twavuze", opens a small table of what was said.
- No text box and no language picker: Kinyarwanda, English or French is inferred from speech.

## Existing application systems reused

- LocaleProvider / useI18n: applies the language inferred from recognized speech to the existing site.
- LocationProvider / useSharedLocation: reuses the existing GPS/location engine and only speaks a result after a fresh result is available.
- POST /api/ishakiro: reuses the existing source-backed assistant engine for Rwanda facts, places, leaders and emergency contacts.
- VERIFIED_EMERGENCY_NUMBERS: validates emergency numbers before preparing a call.
- Existing public routes only: navigation uses an explicit allowlist. “Leaders” maps to the existing #iwacu-local-leaders section, not a fabricated /abayobozi index route.
- useAccessibleDialog: applies focus management, Escape handling and focus restoration to the small panel.

## Speech and language behaviour

The browser Speech Recognition language hint starts from the phone/browser language preference and current site locale. After words are recognized, a conservative language detector may switch the existing LocaleProvider to Kinyarwanda, English or French. Weak evidence does not force a language switch.

This is best-effort, not a guarantee of universal speech auto-detection. The Web Speech API does not guarantee that every browser/device can recognize all three languages within one uninterrupted session. The recognizer may stop and restart with another supported language hint after an explicit unsupported-language error. Real-device testing is still required.

The agent keeps listening while it speaks where the browser permits it. A non-echo interim transcript cancels the current speech. If SpeechSynthesis provides boundary character positions, resume starts from the last reported boundary; where it does not, the current chunk may be repeated. Exact word-level continuation is not claimed on browsers that do not expose that information.

## Voice output: male and female voice

The person can say "Hindura ijwi ry'umugore" / "Hindura ijwi ry'umugabo" (or "Change to female voice", "Change to male voice", "Voix féminine / masculine") at any time; nothing is tapped.

Phones rarely label their voices as male or female, so the agent never goes silent over it:
1. A speech voice of the right language whose own name says it is the requested gender is used as is.
2. Otherwise any voice of that language is used (never one labelled with the opposite gender) and the pitch is lowered (male) or raised (female) so the two choices still sound clearly different.
3. Only a phone with no voice at all for the language keeps the answer as text and says so.

Kinyarwanda: most phones have no Kinyarwanda speech voice. The optional server route /api/remote-agent/tts (Pindo public Kinyarwanda TTS) is used for Kinyarwanda output only when IWACU_REMOTE_AGENT_PINDO_TTS_ENABLED=true. Its voice cannot be switched between male and female. No microphone audio is sent; only the answer text. Without the flag the Kinyarwanda answer stays visible as text.

## Calls and safety

- No number is generated by the model.
- Emergency call preparation accepts only numbers already present in the current verified emergency-number registry.
- The agent announces the number and waits for a spoken confirmation before attempting to open tel:.
- A visible call link remains as a browser/device fallback.
- Public leader calls require a complete public telephone contact returned by the existing IWACU leader API; masked/partial values are rejected.
- No mock fixture values are included in this feature.

## Current limitations requiring validation

1. Speech recognition availability and language support vary by browser and Android device.
2. Full-duplex listening during TTS is best-effort; some devices suspend recognition while speaking.
3. Male/female separation on phones without labelled voices relies on pitch shifting.
4. Kinyarwanda speech output needs the Pindo flag (owner approval); until then Kinyarwanda answers are text only.
5. Browser tel: handling may still require a final user tap, depending on the device/browser.

## Validation

The dedicated GitHub Actions workflow runs remote-agent unit/source-contract tests, existing assistant tests, TypeScript, ESLint and a production build only. It does not deploy.

No Supabase schema/data, Vercel environment settings, secrets, main branch or Production deployment are changed by this feature branch.
